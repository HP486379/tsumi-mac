# 積みMac — 実装仕様 v1.0

## 目的
「買って満足。積んで絶望。」をテーマにした、物理演算と行消しを組み合わせたブラウザ向け落ち物パズルを実装する。テトリスの名称・アセット・特徴的な見た目を複製せず、独自のルール・デザイン・演出にする。

## 技術
- Vite + React + TypeScript(strict)
- Matter.js（2D物理）
- Canvas 2D（プレイフィールド描画）
- Vitest（ユニットテスト）
- Playwright（ブラウザE2E）
- localStorage（ハイスコア）
- 外部サーバー、課金、ログインは不要
- N100クラスのPC、スマホで快適に動作する軽量構成

## フィールド
- 論理グリッド10列×18行。物理ワールド座標と描画座標を分離。
- 論理サイズ360×648を基本とし、画面比に応じて拡大縮小。
- 左右壁・床の衝突、上端の危険ライン。
- リサイズや画面回転に耐える。物理演算60Hz固定タイムステップ。描画はrequestAnimationFrame。
- Matter.EngineをReactの毎フレームstate更新から切り離す。

## 落下・操作
- 上部から1個ずつスポーン。落下中のみ左右操作・90度回転。
- PC: ←→移動 / ↑またはXで右回転 / Zで左回転 / ↓高速落下 / Spaceハードドロップ / P・Esc一時停止。
- スマホ: 左右・回転・高速落下・一時停止の大きなタッチボタン。画面スクロール・長押しの誤動作を防ぐ。
- 重力・衝突・摩擦・反発を反映。重量の違いで下の山への影響が変わる。
- 接地後0.8秒間、速度と位置が安定したら操作対象を確定。確定後も物理ボディとして残し、他の衝撃で動いてよい。
- 操作対象は常に1個。

## ハイブリッド行消し
物理ボディの位置・回転から各グリッドセルへの重なり面積を計算する。各セルの占有率90%以上を占有とし、10セル全て占有された行を「資産整理」対象とする。複数物体が重なる部分は重複加算せず面積の和集合で扱う。

**段階的実装方針：**
1. MVPでは、対象行に交差する物体を丸ごと消す簡易方式を許容する。仕様を画面の遊び方に明記し、消えすぎないよう試験する。
2. 将来版ではボディの分割・再構築により対象行部分だけ除去する。分割が不安定ならMVP方式を維持する。
3. 消去後は残存ボディへ再び重力を適用。ワープや不自然な位置変更を避ける。
4. 行判定は物体が安定したタイミングでのみ実施し、振動による連続発火を防ぐ。

## スコア
- 散財総額：出現した全デバイスの価格合計
- 整理額：消えたデバイスの価格合計（将来的な部分消去は面積按分）
- 積みMac指数：現在残存するデバイス価格合計
- 整理行数、最大コンボ、プレイ時間、レベル
- 同一デバイスの金額を二重計上しない

## ゲームオーバー
- 固定済みボディが危険ラインを継続2秒超えたら終了（スポーン直後は除外）。
- 新たなデバイスが衝突なしにスポーンできなければ終了。
- 結果画面文言：「積みMac崩壊」「起動したMac：0台」「これだけMacを買って、結局N100で開発しました。」

## UI
タイトル / プレイ / ポーズ / 遊び方 / ゲームオーバー。
ゲーム画面で散財総額、積みMac指数、NEXT、レベル、整理行数を表示。結果は再挑戦とテキスト共有（Web Share API、非対応時はコピー）可能。効果音のON/OFF。

## 演出・イベント
- 行消し「資産整理！」、コンボ「断捨離成功！」
- 高額機器落下、衝突、行消しに軽量エフェクト
- MVPで「新製品発表」（次3個を新型に変更）、「整備済製品入荷」（次の散財額20%引き）を実装。残りイベントは将来版。
- 金額は架空のゲーム価格であり、実在製品の販売価格ではないことを明記。

## 開発順序
1. Vite React TSを構築、ビルド成功
2. Matter.jsで5種のボディ生成・落下・接触
3. PC/スマホ操作、固定判定、NEXT
4. 占有率計算とMVP行消し
5. スコア・ゲームオーバー・一時停止
6. UI・演出・イベント・レスポンシブ
7. テストとブラウザによる実機相当検証

## 完了条件
- PC・スマホで開始→操作→列消し→ゲームオーバー→再挑戦可能
- 壁抜け・床抜け・ゲームオーバー誤判定がない
- 占有判定の境界値、回転、行消し、会計の二重計上をVitestで検証
- Playwrightで開始・操作・ポーズ・ゲームオーバー・再挑戦を検証
- npm run buildが成功、コンソールエラーなし
- コード完成だけでなくブラウザで操作し不具合を修正すること
- 実施したテストと未解決の制約を最終報告すること
