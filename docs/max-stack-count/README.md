# 3モード構成と最多積載台数チャレンジ

基準: `remove-tetris-mode` / `b35bf5577ba1150a423e8e8e955043109189eb41`。作業ブランチ: `max-stack-count-mode`。検証日: 2026-10-30。

## プレイできる3モード

|表示名称|内部のルールと物理プロファイル|盤面|記録|
|---|---|---|---|
|テトリスモード|従来の通常モード。内部ID `classic` のまま|360×648px|従来のキー・記録を継続|
|実寸モード|従来の実寸モード。内部ID `real` のまま|540×900px|従来のキー・記録を継続|
|最多積載台数チャレンジ|新しい台数ルール。物理・描画プロファイルは `classic`|360×648px|専用キー `tsumimac.max-stack-count.v1`|

テトリスという名称は旧通常モードの表示名の変更。削除済みのスナップ専用エンジン・配置候補・部分区間消去は復活させていない。`src/game/tetris/` は存在しない。

## 新モードの実装

`CountSim` は既存の `GameSim` を継承し、同じMatterワールド・速度制御・接地/固定・回転・摩擦・質量・筐体を使用する。変更点は以下のルールだけ。

- 行消しは常に0行。定期判定、固定時、明示的なデバッグ呼び出しのいずれでも消去/断片化しない。
- 固定済みで盤面と正の面積で交差するMacを個体IDの集合として数える。操作中と固定待ちは含めない。価格や大きさは台数に影響しない。
- 個体IDは購入時に割り当て、断片へも継承できる。複数の断片が同時に存在しても1台。盤外へ完全に失われた個体のIDは失効し、再計上しない。
- 崩れて動き始めても固定済み状態を維持し、物理演算と台数計測を続ける。従来の赤い危険ライン到達だけでは終了しない。
- 回転後の実際のポリゴンで盤内との交差を判定。部分的なはみ出しは保持し、全体が横/下方向へ外れた場合だけ除去する。上空のボディは重力で戻れるため保持するが、完全に盤外にある間は現在台数に含めない。
- 出現を試みて失敗したチケットを保持し、購入処理を重ねず同じ機種で再試行する。物理演算を続けながら待ち、**3秒連続**で塞がった場合のみ終了。出現に成功すると待ち時間を0へ戻す。一時停止中の時間は含まない。
- 現在台数と1プレイ内の最高台数を別々に管理。盤外落下で現在が減っても最高は維持する。

既存の物理プロファイル型 `GameMode` は変更せず、画面/ルール用の `PlayMode` を分離した。基準ブランチの通常M1/M2薄型72×13.1573604061×72px、M4転用72×36×72px、Studio/Pro/Late2013の形状をそのまま使う。実寸モードの寸法・共通縮尺も無変更。

## 表示・操作・保存

HUDに現在・今回最高・歴代最高・次のMac・出現待機時間を表示する。正面と斜めは同じRenderStateを共有する。PCのキー操作は従来どおり。スマホは新モードだけハードドロップボタンを追加し、左右・回転・高速落下・一時停止も使える。既存2モードのタッチ配置は変えない。

歴代最高は更新時に保存し、タイトルに戻る際も最高台数を保存する。途中で止めても最高は残る。終了結果には今回最高・終了時現在台数・歴代最高・時間を表示。完了したプレイだけ専用記録の `plays` を増やす。旧通常/実寸/旧実寸/過去の廃止モードのキーは移行・削除・上書きしない。

## 検証結果

- **単体テスト: 18ファイル・287件すべて合格**（既存269件、新規18件）。全6機種で旧通常との頂点座標・質量・回転・描画状態が一致。行消しの無効化、固定待ちの除外、盤内崩壊、危険ライン無視、部分はみ出し/完全落下、最高値保持、個体ID重複防止、待機チケット保持/購入重複防止、待機解除、3秒の終了境界、専用記録を確認。
- **本番ビルド: 成功**（`npm run build`、TypeScriptとVite）。
- **Playwright: 44ケース中33件合格、11件は端末条件による対象外スキップ、失敗0**。PC Chrome/Pixel 7相当、WebGL/強制Canvas。既存の行消し・実寸寸法・壁際・回転・接地・断片化・記録・表示同期を含む。
- 新モード4ケースではseed42から通常の左右/回転/ハードドロップで10台以上を積み、既存の固定済み個体が角度0.15rad超または位置24px超動いても、終了せず台数が保持されることを確認。撮影は一時停止して同一フレームを取得。新モードの行数は常に0。
- 別の制御fixtureで1台を完全に盤外へ移し、現在だけがN→N−1、最高Nが維持されることを確認。天井を固定した出現妨害fixtureでは即終了せず待機し、終了・結果保存・再挑戦まで確認。これらのfixtureはプレイヤー機能ではない。
- 旧2モードのハイスコアを既存値で初期化し、新モードを遊んで終了・再挑戦しても保存文字列が一致。旧2モードの既存記録保持テストも実行した。
- 寸法台帳、盤面定数、`physics/`、`grid/`、`rendering/`、既存`systems/`は基準コミットとファイル内容が同一。GameSimへの追加は継承用フックと個体ID継承のみで、従来の計算順序・終了判定・消去を維持。

## 再現方法と制約

`npm test`、`npm run build`、`npm run test:e2e` を使用。実施環境ではインストール済みChromiumを `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` で指定し、4183の本番previewへ接続する外部Playwright設定（URL/出力先のみ変更）を使った。`COUNT_OUTPUT` をPlaywright出力の親フォルダーへ指定して `node scripts/report-max-stack-count.mjs` を実行すると画像と測定値を整理できる。

既存の閉じた壁と床を維持しているため、通常の崩れは基本的に盤内で起きる。完全な盤外落下の経路は制御fixtureでも検証した。出現待機の3秒はシミュレーション時間で、一時停止や処理遅延中の実時間を累積しない。個体IDはプレイごとに再生成し、盤面途中保存は追加していない。スマホはPixel 7エミュレーションで、実機Safariは未検証。既知の未解決テスト失敗はない。
